# kanaterm

日本語IME対応・タブ管理・セッション復元機能を備えた、Windows向けの自作ターミナルエミュレータです。
Electron + [xterm.js](https://xtermjs.org/) + [node-pty](https://github.com/microsoft/node-pty) で構成し、PowerShell を起動します。

---

## 特徴

- **縦タブのサイドバー** — 長いパスも読める幅で、タブごとに名前と色を付けられます
- **セッション復元** — 前回のタブ構成・カレントディレクトリ・画面の表示内容を復元します
- **日本語をそのまま扱える** — 端末とシェルの文字コードを UTF-8 に揃えているため、出力もパス名も文字化けしません
- **カレントディレクトリの自動追従** — シェル統合により `cd` するとタブ名が変わります
- **貼り付けの事故防止** — 複数行を貼り付ける前に内容を確認します
- **調査用のファイルログ** — 起動・終了時の出来事を記録し、後から原因を追えます
- **二重起動しない** — 2回目以降の起動は、既存ウィンドウへ新しいタブとして開きます（起動元のディレクトリを引き継ぎます）

## 動作環境

| 項目 | 要件 |
| --- | --- |
| OS | Windows 10 / 11 |
| シェル | `powershell.exe`（Windows 標準） |
| Node.js | `npm install` の実行に必要 |

### 推奨フォント（任意）

`UDEV Gothic LG` → `BIZ UDGothic` → 等幅フォント の順に使用します。
いずれも未インストールの場合は OS の既定の等幅フォントになり、日本語と英数字の桁幅が揃わないことがあります。

## セットアップ

```
git clone https://github.com/Helicon1968/kanaterm.git
cd kanaterm
npm install
```

## 起動

```
npm start
```

または `start.bat` をダブルクリックしてください。
`start.bat` は自身の場所を基準に動くため、どこから実行しても構いません。`node_modules` が無ければ初回だけ `npm install` を自動実行します。

## 使い方

### キーボードショートカット

| キー | 動作 |
| --- | --- |
| `Ctrl` + `Shift` + `T` | 新しいタブ（現在のタブと同じディレクトリで開く） |
| `Ctrl` + `Shift` + `W` | タブを閉じる（最後の1枚ならウィンドウを閉じる） |
| `Ctrl` + `Tab` | 次のタブへ |
| `Ctrl` + `Shift` + `Tab` | 前のタブへ |
| `Ctrl` + `V` / `Ctrl` + `Shift` + `V` | 貼り付け |
| `Ctrl` + `Shift` + `I` | DevTools の開閉 |

`Ctrl` + `C` などその他のキーは、すべてシェルへそのまま渡されます。

### マウス操作

| 操作 | 動作 |
| --- | --- |
| ドラッグで選択 | 選択と同時にクリップボードへコピー |
| タブ名をダブルクリック | 名前を変更（空にすると自動表示へ戻る） |
| タブをドラッグ | 並べ替え（行の上半分／下半分で挿入位置が決まる） |
| 画面を右クリック | 端末のメニュー |
| タブを右クリック | タブのメニュー |

### 右クリックメニュー

**画面（端末本体）**

- 新規タブ / 貼り付け / 閉じる
- フォントサイズ — 11 / 14 / 18 / 22 pt
- 配色 — ダーク（既定）／ライト／ハイコントラスト／紺／緑／濃赤
- 複数行の貼り付け前に確認する（ON/OFF）
- ログ — 詳細ログ（デバッグ）の記録 ON/OFF、ログフォルダを開く

**タブ**

- 色 — なし／赤／橙／黄／緑／青／紫／グレー
- 名前を変更
- 閉じる

### タブ名の決まり方

手動で名前を付けていればそれを優先し、付けていなければカレントディレクトリを短縮して表示します（`...\Dropbox\AI` のように末尾2階層）。手動で付けた名前は `cd` しても変わりません。

## セッション復元について

次回起動時に復元されるものと、されないものがあります。

| 復元される | 復元されない |
| --- | --- |
| タブの構成・並び順 | 実行中だったプロセス |
| 各タブのカレントディレクトリ | シェルの変数・履歴 |
| タブの名前と色 | 画面の実際の状態（あくまで見た目の写し） |
| 最後に見ていたタブ | |
| 画面の表示内容（スクロールバック） | |

画面の表示内容は**見た目のスナップショット**です。復元直後の画面は前回終了時の見た目ですが、シェル自体は新しく起動した状態です。

- 保存は10秒ごと、および終了直前に行います
- タブを明示的に閉じた場合、そのタブの表示内容は破棄します
- 何か入力すると復元内容の保護は解除され、以後は通常の描画になります

## 複数行の貼り付け

シェルは改行を受け取った時点でその行を実行します。複数行を貼り付けると各行がそのまま実行されてしまうため、**2行以上の場合は貼り付け前に内容を確認します**。

- 末尾の改行1つは行数に数えません（「コマンド1行＋改行」は確認なしで貼り付けます）
- `Enter` で貼り付け、`Esc` でキャンセル
- 「今後この確認を表示しない」は、**貼り付けを選んだ時だけ**反映されます
- 無効にしたあとは、右クリックメニューの「複数行の貼り付け前に確認する」で戻せます
- ブラケットペーストに対応したシェルでは各行が実行されないため、確認を省略します

## 設定とデータの保存場所

設定はこのPC単位で保持され、`%APPDATA%\kanaterm` 配下に保存されます。**プロジェクトフォルダには何も書き込みません。**

| パス | 内容 |
| --- | --- |
| `%APPDATA%\kanaterm\state.json` | ウィンドウ位置・タブ構成・表示設定 |
| `%APPDATA%\kanaterm\scrollback\<タブID>.txt` | 各タブの画面内容 |
| `%APPDATA%\kanaterm\logs\kanaterm-YYYYMMDD.log` | ログ（7日より古い分は起動時に自動削除） |

`state.json` の `settings`:

| キー | 既定値 | 意味 |
| --- | --- | --- |
| `fontSize` | `14` | フォントサイズ（pt） |
| `theme` | `"dark"` | 配色 |
| `confirmMultilinePaste` | `true` | 複数行の貼り付け前に確認する |
| `debugLog` | `false` | 詳細ログ（DEBUG）を記録する |

これらを消せば初回起動時の状態に戻ります。フォルダごと削除しても、次回起動時に作り直されます。

> **注意**: 保存先はアプリ名で決まるため、このフォルダを別の場所にコピーして起動しても、**設定とタブは同じものを共有します**。

## ログ（不具合の調査）

DevTools（`Ctrl` + `Shift` + `I`）で見えるのはレンダラー側の、しかも開いている間だけです。起動時・終了時の出来事はその時点で終わっているため、ファイルにも記録しています。

| レベル | 記録するタイミング | 内容 |
| --- | --- | --- |
| INFO 以上 | 常時 | 起動・終了、タブの生成／破棄、シェルの終了コード、保存の失敗、cwd の退避 |
| DEBUG | 設定を有効にした時だけ | 設定変更、状態の保存、内部の細かい経過 |

レンダラー側で起きた例外（`window.onerror` / `unhandledrejection`）も、DevTools を開いていなくてもスタック付きで記録します。

**詳細ログの有効化**: 画面を右クリック → ログ → 詳細ログ（デバッグ）を記録する
設定は即座に反映されます（再起動不要）。ただし起動時の処理の詳細は次回の起動から記録されます。

> **記録しないもの**: PTY の入出力そのもの（打った内容・画面の中身）は、DEBUG でも記録しません。パスワードを入力する場面があるためです。

## 開発メモ

手を入れる際に踏みやすい落とし穴を挙げておきます。

- **プリセットは `presets.js` に集約する**
  配色やタブ色を main 側（メニューの選択肢）と renderer 側（実際の描画色）に別々に書くと、片方だけ直したときに「メニューには出るが色が付かない」というずれが起きます。

- **タブの並び順は DOM が正**
  並べ替えは DOM 要素を動かして表現しています。`Map` の列挙順は生成順のままなので、順序の判断には必ず `tabIdsInOrder()` を使ってください。

- **`shell-integration.ps1` は UTF-8 BOM 付きで保存する**
  Windows PowerShell 5.1 は BOM の無いファイルをシステムのコードページ（日本語環境では CP932）として読むため、BOM を落とすと日本語コメントが壊れて構文エラーになります。

- **ショートカットは `stopPropagation()` まで行う**
  xterm.js は `defaultPrevented` を見ずにキーをシェルへ送ります。`preventDefault()` だけでは制御文字（`Ctrl` + `V` なら `^V`）が流れてしまいます。

- **終了時の保存は `closed` で行う**
  レンダラー発の `window.close()`（最後のタブを閉じる経路）では `BrowserWindow` の `close` イベントが発火しません。保存の確定は `closed` で、かつ内部状態を凍結する前に行う必要があります。

- **ウィンドウサイズは `getBounds()` を無条件に読まない**
  高DPI（125% など）では `setBounds()` した値と `getBounds()` の戻りが数 px ずれます。保存のたびに読み直すと、起動のたびにウィンドウが少しずつ育ちます。自分で適用した値とほぼ同じ変化は無視しています。

上記はいずれも実際に踏んだ不具合です。原因と、採用しなかった案を含む詳しい経緯は [docs/HISTORY.md](docs/HISTORY.md) を参照してください。

## 既知の制限

- **Windows専用です。** `powershell.exe` の起動と Windows のパス表記（`\` 区切り、ドライブレター）に依存しています。
- **セッション復元は見た目の写しであり、プロセスは復元されません。** 実行中だったコマンド、シェルの変数、コマンド履歴は引き継がれません（[セッション復元について](#セッション復元について)）。
- **複数行を貼り付けると各行がそのまま実行されます。** PowerShell + ConPTY がブラケットペーストに対応していないためで、確認ダイアログはこれを承知の上で貼り付けるための確認です。
- **設定の保存先はアプリ名で決まります。** このフォルダを複数の場所にコピーしても、設定とタブは同じものを共有します。切り分けるには起動時に `--user-data-dir` を指定する必要があります。
- **4px以下の微細なウィンドウサイズ変更は保存されません。** 高DPI環境で `setBounds()` と `getBounds()` の間に生じる丸め差を無視しているためです（無視しないと起動のたびにウィンドウが少しずつ育ちます）。
- **タブを閉じると、そのタブの画面内容は破棄されます。** 誤って閉じた場合、表示内容は元に戻せません。
